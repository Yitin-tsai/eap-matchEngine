# eap-matchEngine - LLM Context

> Port 8082 | Context path `/match-engine`

## Ownership

- Redis order book and price-time matching decision.
- Durable append-only `trade_executions` fact.
- Trade transactional outbox.
- Deferred Redis reservation-cleanup tasks and crash reconciliation.
- TDA bid collection, auction schedules, clearing-price calculation, and results.

MatchEngine does not own Wallet settlement, Order projection, or downstream completion state.

## Current Flow

```text
OrderConfirmedEvent
  -> Redis Lua reserve/match
  -> DB transaction:
       trade_executions
       trade_outbox
       optional reservation_cleanup_tasks
  -> TradeOutboxRelay publishes TradeExecutedEvent
  -> ReservationCleanupWorker finalizes Redis cleanup
```

Order and Wallet consume `TradeExecutedEvent` directly. The legacy `OrderMatchedEvent`, per-service completion callbacks, marker queues, and `trade_completion_view` are retired.

## TDA Flow

```text
scheduled create -> direct AuctionCreatedEvent publish
AuctionBidConfirmedEvent -> collect Wallet-approved bid in Redis
scheduled clear -> direct AuctionClearedEvent publish to Order and Wallet
```

Auction lifecycle publication currently bypasses the CDA trade outbox. TDA is implemented but has no equivalent published CDA capacity/recovery evidence.

## Recovery

- `trade_id` makes trade recording idempotent.
- Outbox retry/backoff handles RabbitMQ publication failures.
- Cleanup tasks use persistent status/leases/retries.
- ReservationReconciler compares stale Redis reservations with durable trades and releases or completes them.

## Known Risk

The current Spring `taskScheduler` has one worker shared by cleanup, trade outbox polling, reconciliation, and auction jobs. A 2026-08-07 deep run observed a 9.380s cleanup batch and common downstream lag. Scheduler isolation is pending validation.
